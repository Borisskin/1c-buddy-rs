## Общий договор

Сервер публикует восемь основных имён. Клиент может добавлять к ним собственный префикс пространства имён; находить инструмент по конечному имени.

Не передавайте поля, которых нет в описаниях ниже: сервер игнорирует неизвестные поля, но клиент не должен полагаться на это поведение. Не придумывайте параметры, которых нет ниже.

Содержательные строки обычно должны иметь длину от 4 знаков. Текущий сервер ограничивает строки настраиваемым пределом до 100 000 скалярных значений Unicode. Передавать короткий, самодостаточный контекст вместо всего проекта.

Поля `ssl_version` обозначают версию Библиотеки стандартных подсистем (БСП), а не версию TLS или SSL.

Пустые `ssl_version` и `configuration` заменяются настройками сервера `DEFAULT_SSL_VERSION` и `DEFAULT_1C_CONFIGURATION`. Если пользователь не назвал значение, поле лучше опустить.

Каждый вызов создаёт отдельную беседу во внешней службе. Не предполагать, что следующий вызов помнит предыдущий; повторять необходимый контекст.

## `ask_1c_ai`

Использовать для общего вопроса по платформе, подходу к разработке или прикладному сценарию, когда не требуется отдельный точный поиск.

| Поле | Обязательность | Значение |
|---|---|---|
| `question` | обязательно | Конкретный вопрос на русском языке |
| `programming_language` | необязательно | `""`, `BSL`, `SQL`, `JSON` или `HTTP` |
| `ssl_version` | необязательно | Версия БСП |
| `configuration` | необязательно | Название конфигурации |

```json
{
  "question": "Как безопасно организовать повторное проведение документа?",
  "programming_language": "BSL",
  "configuration": "ERP"
}
```

Не использовать вместо поиска по документации или ИТС, когда пользователь просит точный подтверждённый факт.

## `explain_1c_syntax`

Использовать для объяснения конкретного элемента языка, объекта, коллекции, метода или типа платформы.

| Поле | Обязательность | Значение |
|---|---|---|
| `syntax_element` | обязательно | Название объясняемого элемента |
| `context` | необязательно | Существенный контекст использования |
| `ssl_version` | необязательно | Версия БСП |
| `configuration` | необязательно | Название конфигурации |

```json
{
  "syntax_element": "ТаблицаЗначений",
  "context": "Нужно сгруппировать строки по номенклатуре в серверной процедуре"
}
```

Если точное поведение зависит от версии платформы, сначала использовать `search_1c_documentation`.

## `check_1c_code`

Использовать для синтаксической проверки или обзора BSL-кода.

| Поле | Обязательность | Значение |
|---|---|---|
| `code` | обязательно | Проверяемый фрагмент BSL |
| `check_type` | необязательно | `syntax` по умолчанию; `review`, `logic` или `performance` |
| `extended` | необязательно | `false` по умолчанию; только для `syntax` включает обогащение стандартами 1С |

Синтаксическая проверка:

```json
{
  "code": "Процедура Выполнить() Экспорт\n    Сообщить(\"Готово\");\nКонецПроцедуры",
  "check_type": "syntax",
  "extended": true
}
```

Обзор:

```json
{
  "code": "Функция ПолучитьОстаток(Номенклатура)\n    // проверяемый код\nКонецФункции",
  "check_type": "review"
}
```

Значения `logic` и `performance` сохранены для совместимости и выполняются как `review`; не обещать пользователю отдельный специализированный режим.

Проверка `syntax` не получает глобальный контекст. Замечания о необъявленных переменных и методах могут быть ложными, если определения находятся вне переданного фрагмента.

## `modify_1c_code`

Использовать только по явному заданию изменить код: исправить причину ошибки, переработать структуру или добавить возможность.

| Поле | Обязательность | Значение |
|---|---|---|
| `instruction` | обязательно | Что изменить и какой результат ожидается |
| `code` | необязательно | Исходный код |

```json
{
  "instruction": "Устранить повторные запросы в цикле, сохранив результат процедуры и её внешний договор",
  "code": "Процедура ЗаполнитьЦены()\n    // исходный код\nКонецПроцедуры"
}
```

Формулировать проверяемые требования: сохранить сигнатуру, режим выполнения, обработку пустых значений и ожидаемый вид результата. Если важны версии платформы, конфигурации или БСП, включить их в `instruction`: отдельных полей для них нет. После ответа отдельно вызвать `check_1c_code` для полученного кода сначала с `check_type="syntax"`, затем с `check_type="review"`.

## `search_1c_documentation`

Использовать для точного поиска по документации платформы: объекты, методы, свойства, параметры и синтаксис.

| Поле | Обязательность | Значение |
|---|---|---|
| `query` | обязательно | Предметный поисковый запрос |
| `version` | необязательно | `v8.5.1` по умолчанию; формат `v8.x.x` или `v8.x.x.x` |

```json
{
  "query": "Общая информация о HTTPСоединение и список методов",
  "version": "v8.3.27"
}
```

Для обзорной темы использовать формулировки «Общая информация о …», «Список всех …» или «Все …». Если пользователь указал версию, обязательно передать её.

## `search_its`

Использовать для стандартов и правил разработки, методических материалов, практических примеров, конфигураций и продуктов 1С, EDT и Конфигуратора.

| Поле | Обязательность | Значение |
|---|---|---|
| `query` | обязательно | Предметный поисковый запрос |
| `ssl_version` | необязательно | Версия БСП |
| `configuration` | необязательно | Название конфигурации |

```json
{
  "query": "Стандарт обработки ошибок при вызове внешнего сервиса",
  "ssl_version": "3.1.10",
  "configuration": "Бухгалтерия предприятия"
}
```

За фактическими сведениями об экосистеме 1С обращаться к этому инструменту, а не отвечать по памяти. Если нужен полный найденный материал, передать его идентификатор в `fetch_its`.

## `fetch_its`

Использовать после `search_its` для чтения найденного документа или каталога. Без предварительного поиска использовать только для осознанного исследования структуры ИТС.

| Поле | Обязательность | Значение |
|---|---|---|
| `id` | необязательно | `root` по умолчанию |

Допустимы специальные значения `root`, `superior`, `v8std` и выданные поиском идентификаторы вида `its-...-hdoc` или `its-...-hdir`, иногда с одним или двумя якорями через `/`.

```json
{
  "id": "its-example-hdoc"
}
```

Не изобретать идентификатор. Брать его из результата `search_its` или из структуры, возвращённой самим `fetch_its`.

## `diff_1c_documentation_versions`

Использовать для сравнения документации платформы между двумя версиями.

| Поле | Обязательность | Значение |
|---|---|---|
| `version_a` | обязательно | Более ранняя версия |
| `version_b` | обязательно | Более поздняя версия |
| `query` | необязательно | Предметная область сравнения |

```json
{
  "version_a": "v8.3.24",
  "version_b": "v8.3.27",
  "query": "HTTPСоединение"
}
```

Сохранять хронологический порядок версий. Если содержательная разница пуста, но ответ перечисляет изменённые файлы, уточнить предметный запрос.

## Ограничения выполнения

- Вопросы, пользовательский код и поисковые параметры передаются `https://code.1c.ai`; автономного режима нет.
- Одновременно выполняются один или два вызова в зависимости от настройки сервера; ещё восемь могут ожидать.
- Ожидание очереди ограничено 30 секундами, весь вызов — 300 секундами.
- Входящий и исходящий кадр MCP ограничен 2 МиБ.
- Превышение предела возвращает ошибку, а не частичный успешный результат.
- Основные имена чувствительны к регистру. Использовать имена из этого справочника, а не прежние псевдонимы.
