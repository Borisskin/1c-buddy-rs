## Why

Сценарий непрерывной проверки и выпуска сейчас собирает и проверяет только Windows x86-64, поэтому пользователи Linux и macOS не получают проверяемых исполняемых файлов из той же редакции исходников. Локальные образцы в `vendor` подтверждают пригодный для этого проекта способ: отдельная собственная сборка на штатной среде каждой операционной системы с единым последующим выпуском.

## What Changes

- Сохраняется действующая сборка Windows x86-64 и её специальные проверки PE, архитектуры и статической библиотеки времени выполнения MSVC.
- Добавляются проверка и выпуск для Linux x86-64 с целью Rust `x86_64-unknown-linux-gnu`.
- Добавляются проверка и выпуск для macOS на Apple Silicon с целью Rust `aarch64-apple-darwin`.
- Сборки выполняются на штатных средах Windows, Linux и macOS из одной редакции исходников и с одной закреплённой версией Rust.
- Для Linux и macOS создаются архивы `tar.gz`; каждый архив содержит исполняемый файл и тот же обязательный набор сопроводительных файлов, что и поставка Windows.
- Для каждого исполняемого файла и архива создаются контрольные суммы SHA-256; публикация получает все три архива и общий проверяемый перечень контрольных сумм.
- Документация установки и настройки дополняется командами и путями для Linux и macOS.
- **BREAKING** отсутствуют: имена средств MCP, их схемы, настройки и действующая поставка Windows не меняются.

## Capabilities

### New Capabilities

- `cross-platform-release`: целевые операционные системы и архитектуры, собственные среды сборки, состав архивов, контрольные суммы, объединение результатов и правила публикации Windows, Linux и macOS.

### Modified Capabilities

Постоянные спецификации проекта пока отсутствуют; изменение не объявляет модификацию прежней возможности. Действующие требования Windows из незавершённого изменения сохраняются как ограничение проектирования.

## Impact

- Сценарий `.github/workflows/release.yml`: название, группа одновременного выполнения, матрица проверок, две дополнительные сборки кандидатов, объединение выпускных материалов и публикация.
- Документация `README.md` и `README_FULL.md`: поддерживаемые системы, имена архивов, установка, настройка клиентов и проверка контрольных сумм.
- Сборочный договор: `build.rs` уже пропускает ресурсы Windows на других целях; статическая MSVC задаётся только в заданиях Windows отслеживаемого сценария и проверяется договорным тестом.
- Сторонние библиотеки и договор MCP не меняются.
- Расход времени GitHub Actions увеличится за счёт двух дополнительных штатных сред; отказ одной цели не должен отменять уже запущенные независимые сборки.
