## Purpose

Определяет проверяемую поставку одной редакции `onec-buddy-mcp` для Windows, Linux и macOS с явными целями Rust, составом архивов и контролем неизменности выпускных материалов.

## ADDED Requirements

### Requirement: Поддерживаемые цели выпуска

Система выпуска ОБЯЗАНА (MUST) собирать три отдельные поставки:

- Windows x86-64 для `x86_64-pc-windows-msvc`;
- Linux x86-64 для `x86_64-unknown-linux-gnu`;
- macOS Apple Silicon для `aarch64-apple-darwin`.

Поддержка Linux на ARM, macOS на Intel и универсального файла macOS НЕ ВХОДИТ в это изменение.

#### Scenario: Выполнена проверка запроса на слияние

- **WHEN** открыт или обновлён запрос на слияние в `main`
- **THEN** каждая из трёх целей ДОЛЖНА пройти `cargo test --locked --target <цель> --all-features`
- **AND** ошибка одной цели ДОЛЖНА делать общую проверку изменения неуспешной

#### Scenario: Запущен выпуск

- **WHEN** выпуск вручную запущен из ветви `main`
- **THEN** система ДОЛЖНА создать отдельный кандидат для каждой из трёх поддерживаемых целей

#### Scenario: Запущена пробная сборка ветви

- **WHEN** сценарий вручную запущен из ветви, отличной от `main`
- **THEN** система ДОЛЖНА создать и сохранить для скачивания отдельный кандидат каждой из трёх поддерживаемых целей
- **AND** задание публикации НЕ ДОЛЖНО запускаться, а метка и выпуск НЕ ДОЛЖНЫ создаваться

### Requirement: Собственная среда каждой операционной системы

Каждый кандидат ОБЯЗАН (MUST) собираться на штатной среде своей операционной системы из одной и той же редакции исходников, с одной закреплённой версией Rust и с `Cargo.lock`.

#### Scenario: Сборка трёх кандидатов

- **WHEN** начались выпускные сборки Windows, Linux и macOS
- **THEN** Windows ДОЛЖНА собираться на Windows, Linux — на Linux, macOS — на macOS
- **AND** значение `source_sha` у всех трёх кандидатов ДОЛЖНО совпадать с редакцией запущенного сценария

#### Scenario: Одна цель завершилась ошибкой

- **WHEN** одна из независимых выпускных сборок завершается ошибкой
- **THEN** уже запущенные сборки других целей НЕ ДОЛЖНЫ отменяться
- **AND** публикация общего выпуска ДОЛЖНА быть запрещена

### Requirement: Сохранение гарантий Windows

Добавление Linux и macOS НЕ ДОЛЖНО ослаблять действующие проверки Windows: цель MSVC, статическое подключение среды выполнения, проверка PE x86-64, неизменный исполняемый файл и проверка вложенного SHA-256 ОБЯЗАНЫ (MUST) сохраняться.

#### Scenario: Создан кандидат Windows

- **WHEN** выпускная сборка Windows завершена
- **THEN** кандидат ДОЛЖЕН пройти прежние проверки PE, x86-64 и зависимостей MSVC
- **AND** SHA-256 файла внутри архива ДОЛЖЕН совпадать с SHA-256 замороженного кандидата

### Requirement: Архивы поставки

Система выпуска ОБЯЗАНА (MUST) создавать:

- `onec-buddy-mcp-windows-x86_64.zip`;
- `onec-buddy-mcp-linux-x86_64.tar.gz`;
- `onec-buddy-mcp-macos-aarch64.tar.gz`.

Каждый архив ДОЛЖЕН содержать ровно исполняемый файл своей системы, `README.md`, `README_FULL.md`, `LICENSE` и `.env.example`. Исполняемый файл Windows ДОЛЖЕН называться `onec-buddy-mcp.exe`, а исполняемые файлы Linux и macOS — `onec-buddy-mcp`.

#### Scenario: Проверяется состав архива

- **WHEN** кандидат упакован
- **THEN** перечень его записей ДОЛЖЕН точно совпадать с пятью обязательными файлами
- **AND** посторонние файлы и внешний родительский каталог НЕ ДОЛЖНЫ попадать в архив

### Requirement: Контрольные суммы и сведения о сборке

Для каждой цели система ОБЯЗАНА (MUST) записывать SHA-256 исполняемого файла и архива, цель Rust, имя среды, версию пакета, метку выпуска и редакцию исходников. Общий `SHA256SUMS.txt` ДОЛЖЕН содержать проверенные SHA-256 всех трёх публикуемых архивов.

#### Scenario: Выпускные материалы объединяются

- **WHEN** все три кандидата загружены в задание публикации
- **THEN** задание ДОЛЖНО повторно вычислить SHA-256 каждого архива
- **AND** значение ДОЛЖНО совпасть со сведениями соответствующей сборки
- **AND** общий перечень контрольных сумм ДОЛЖЕН быть создан только из повторно проверенных значений

#### Scenario: Контрольная сумма не совпала

- **WHEN** архив, вложенный исполняемый файл или сведения о сборке не совпадают с ожидаемыми значениями
- **THEN** публикация ДОЛЖНА завершиться ошибкой до создания метки и выпуска

### Requirement: Атомарная публикация

Публичный выпуск ОБЯЗАН (MUST) создаваться одним заданием только после успешной проверки всех трёх кандидатов. Выпуск ДОЛЖЕН прикреплять три архива и общий `SHA256SUMS.txt` к одной метке версии.

#### Scenario: Все кандидаты проверены

- **WHEN** три архива принадлежат одной версии и одной редакции исходников и прошли повторную проверку
- **THEN** система ДОЛЖНА создать одну метку и один выпуск
- **AND** все три архива и общий перечень контрольных сумм ДОЛЖНЫ быть доступны в этом выпуске

#### Scenario: Метка или выпуск уже существует

- **WHEN** предварительная или заключительная проверка обнаруживает существующую метку либо выпуск той же версии
- **THEN** новый выпуск НЕ ДОЛЖЕН создаваться или перезаписывать существующий

### Requirement: Документация по каждой системе

Пользовательская документация ОБЯЗАНА (MUST) называть поддерживаемые цели, архивы, способы проверки контрольной суммы и примеры абсолютных путей запуска для Windows, Linux и macOS.

#### Scenario: Пользователь устанавливает файл своей системы

- **WHEN** пользователь открывает краткое или подробное руководство
- **THEN** руководство ДОЛЖНО позволять выбрать правильный архив
- **AND** подробное руководство ДОЛЖНО описывать распаковку, право на выполнение для Unix и настройку клиента MCP с абсолютным путём
